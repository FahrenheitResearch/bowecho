# BowEcho v0.26.2

This is a quick ORD European-radar fix release for sites where the Open Radar
Data archive exposes useful products across separate object lanes.

## ORD Radar Fixes

- Fixed Dublin / `iedub` loading reflectivity from the wrong ORD lane.
- ORD now evaluates both `PVOL` and `SCAN` candidates instead of accepting the
  first non-empty listing.
- Candidate priority is now:
  1. reflectivity + velocity
  2. reflectivity-only
  3. velocity-only
  4. other products
- This keeps complete dual-pol/velocity-capable frames preferred, while still
  allowing a reflectivity-only SCAN lane to beat a velocity-only PVOL lane.
- Recent-loop and archive-hour planning now use the same lane scoring, so the
  fix applies beyond Dublin when another ORD site has a similar split-lane
  product layout.
