# BowEcho v0.33.3 — CM1, faster P3 CUDA, and SimSat v0.2.1

BowEcho v0.33.3 adds a first-class native-CM1 workflow, reduces the CUDA
request overhead in the research P3/ISHMAEL radar path, updates the embedded
SimSat renderer to v0.2.1, reconstructs the recoverable part of a WRF
namelist, and fixes satellite and WoFS display failures.

## Native CM1 workflow

**Windows > CM1** now opens a dedicated native-output workspace instead of
sending CM1 files through the WRF reader.

- BowEcho inventories modern CM1 r20.3+, legacy r18/r19, and legacy COARDS
  NetCDF topologies. It accepts complete domains, identifies one-file MPI
  tiles that still need assembly, and reports unsupported dimensions rather
  than guessing.
- Native 2-D and 3-D scalar fields can be stored in Models. Arakawa-C `u`,
  `v`, and `w` are averaged from their documented adjacent faces onto the
  scalar grid; their original staggering remains visible in provenance.
- A multi-record file can become one ordered model loop using its exact CM1
  elapsed-time coordinate and official simulation-start globals. The
  NetCDF4/HDF5 time-coordinate fallback also covers legacy files whose time
  dimension was omitted by the normal index.
- Every map import requires an explicit domain-center latitude/longitude.
  **Follow domain** keeps a storm-following grid pinned to that anchor.
  **Fixed world** preserves source displacement only when exact positions are
  available; matching `cm1out_diag_XXXXXX.nc` files can supply those positions.
  BowEcho does not integrate `umove`/`vmove` into invented geolocation and does
  not treat `ctrlat`/`ctrlon` as a map projection.
- The window can read an exact native vertical column at any scalar cell. A
  separate meteorological-readiness panel derives pressure, temperature,
  dewpoint, and grid-relative/earth-relative winds only when exact, unit-bearing
  `th`, `prs`, `qv`, `zhval`, and horizontal-wind inputs are present. Use of
  CM1's default `Rd/Cp/Rv` constants is an explicit opt-in because native
  output does not identify the special constants used by test cases 4 and 5.
- A radar-ready complete domain can build scalar native **REF/VEL** through
  the existing polar renderer. This path requires native 3-D `dbz`, physical
  `zhval`, horizontal and vertical winds, exact time, explicit placement, and
  either native `zs` terrain or an explicit flat-domain choice. The first
  completed tilt is shown while the remaining tilts process.

The CM1 radar path is intentionally narrow in this release: it is CPU sampled,
uses one frozen model record and standard 4/3-Earth geometry, and consumes the
file's native scalar `dbz`. It does not extrude 2-D `cref`, assemble MPI tiles,
synthesize dual-pol, run T-matrix or WRF refractivity, recompute reflectivity,
or interpolate between adjacent WRF atmospheres. CM1 model height has no
declared MSL datum, so the thermodynamic table is not silently passed to the
MSL-labelled Sounding viewer.

See `docs/cm1-guide.md` for a practical walkthrough and file requirements.

## P3/ISHMAEL CUDA request pipeline

When a supported NVIDIA device is selected, the raw-state P3/ISHMAEL research
route now prepares bounded groups of gates on the CPU, submits admitted
dry-oblate and dry-prolate lookup nodes as stable role sweeps, and finishes
results in source order. Cancellation remains bounded. If a CUDA batch fails,
the whole prepared group replays on the scalar CPU path instead of mixing GPU
and CPU answers. Reusable geometry, role-sweep storage, and CUDA worker scratch
remove additional hot-loop allocation.

One measured RTX 5090 request/kernel microbenchmark used 1,024 Center gates,
three particle populations per gate, and 32 admitted nodes per population. It
reduced service requests from 3,072 to 32 (96x) and reduced the measured
request-plus-LUT-kernel interval from 47.979688 s to 0.505017 s (95.006x), with
exact component-bit CPU/GPU parity.

That number is deliberately not an end-to-end radar-volume promise. File I/O,
raw-state interpolation, CPU admission and closure, rain and bridge work,
beam/ray sampling, propagation, and rendering remain outside that benchmark;
actual speedup depends on the file, scan, quadrature, particle population, GPU,
and how much work reaches the CUDA tables. The P3/ISHMAEL operator remains
research-only and not independently validated.

## Annotated WRF namelist reconstruction

The **Open WRF / NetCDF** card in **Windows > WRF** now includes **Extract
namelist…**. It reads one raw wrfout and saves
`namelist.reconstructed.input` with three deliberately distinct classes:

- active assignments are exact values stored as wrfout globals and safe to
  map back to that file's represented domain;
- exact context that cannot safely become namelist syntax remains commented;
- dimensions or lower bounds inferred from file structure remain comments;
- settings that cannot be recovered remain explicit comments.

The output identifies its source and warns at the top that it is partial, is
not the original `namelist.input`, and cannot reproduce the run. Run duration,
many I/O and boundary settings, omitted scheme options, input data, tables,
source revision, build options, and the runtime environment still require the
original experiment record.

## Satellite display and live-follow fixes

- Full-resolution frames retain a practical preview area in short or docked
  Satellite windows instead of collapsing into a tiny dark thumbnail after
  the source controls consume the pane height.
- A satellite map viewport containing no visible source pixels now displays
  an explicit coverage/transparent-IR notice instead of looking like a broken
  black layer.
- Live GOES follow selects the run that was just written after the store scan.
- Saved runs are ordered by their actual frame times, so an old SimSat run can
  no longer mask a healthy live GOES ingest.

## WoFS midnight and map-drape fixes

- WoFS keeps each API init as its exact `YYYYMMDDHHMM` token. A 0300 UTC init
  belonging to the next calendar day now uses that date in imagery, sounding,
  hierarchy, and georeference requests instead of constructing a stale path
  from the nominal run date.
- A WoFS map drape keeps loading and following radar time after its control
  window is closed; closing the window no longer removes or freezes the layer.
- The WoFS viewer now distinguishes **Loading WoFS frame…** from **Frame
  unavailable at the WoFS source** instead of presenting an unexplained black
  panel.

## SimSat v0.2.1

The first-class **Windows > SimSat** workspace is pinned to the exact public
SimSat v0.2.1 release commit
`22dd23b2b956360c53ca6b7b2b445fe76202c392`.

- Surface illumination no longer applies an unintended second limb-darkening
  factor to land, water, or glint.
- Fresh panes and **Recommended** use the reviewed surface-only ground lift of
  1.10. The neutral 1.0 override remains available.
- Independent twilight terrain recovery exposes enable, knee, gamma, and
  maximum-gain controls. Recommended uses `0.30 / 0.50 / 4.0`; the effect
  fades in from -6° to 0° solar elevation, remains full through +4°, and
  returns to identity by +12°.
- GPU preview retains both post-light terrain controls and uses the same
  post-view formulas as the CPU path.
- **CIMSS Style** is the recommended Band-13 presentation. Explicitly choosing
  an IR or water-vapor product selects CIMSS and recolors the shared Satellite
  player; startup in the same product still preserves an explicitly saved
  palette. Natural NOAA-heritage grayscale remains available.

SimSat pane state advances from schema 2 to schema 3. A saved v0.2.0 payload is
migrated once without changing its rendered appearance: its existing ground
lift is retained and twilight recovery is written as off. Applying
**Recommended** is the deliberate opt-in to the v0.2.1 calibration. Compact
production caches remain SSB v6 and ScienceCloudF16 remains isolated in v7, so
the update does not force a compact-cache rebuild. Source paths, jobs,
progress, and output remain session-only as before.
